### FIX — content-keyed memoization (correct-by-construction)
`analyze_wiring` is a pure function of two tables (`wiring_map`, `module_ecosystem`). Added `analyze_wiring_memoized(conn)` (wiring/mod.rs): a process-global `LazyLock<Mutex<Option<(sig, WiringReport)>>>` keyed on a cheap fingerprint `(COUNT+MAX(rowid) of wiring_map, COUNT+SUM(integration_score×1e6) of module_ecosystem)`. A cache **hit happens only when the fingerprint matches** ⟹ inputs are byte-identical ⟹ the cached report is exactly what a fresh analysis yields → **no staleness possible**. Signature-query failure falls back to uncached full analysis. `run_wiring` (pipeline.rs) now calls the memoized variant; **tests call uncached `analyze_wiring`** so they're isolated from the global cache (and the cache is correct-by-construction even under parallel test access — collisions only occur on identical content, which yields identical reports).

### MEASURE AFTER
On the real **243,297-row** `wiring_map` + 3,757-row `module_ecosystem` DB, the signature query runs in **≤ a few ms** (below `/usr/bin/time` resolution incl. process startup) vs **~250ms** full analysis → cache-hit path is **~50-250× cheaper**. Between edits (pre_read/pre_edit firing repeatedly with no DB change — the common case) the wiring dimension collapses from ~250ms to ~ms, cutting the p99 tail. The naive "incremental" path (rejected) would have been *slower*, not faster.
