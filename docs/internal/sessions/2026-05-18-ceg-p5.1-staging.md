## 1. What P5.1 adds

A code body routed through the `X0..X9` gateway has to live somewhere on disk
before X5 SANDBOX or X8 SUPERVISED-EXEC can invoke it. Writing it to `/tmp`
severs the thread: the gateway computes a verdict for "this body", but the
`/tmp` file carries no record of which session produced it or what was already
decided. A later invocation of the same path cannot recover that verdict and
re-analyses from scratch — CEG Pln2 risk **R9** (heredoc temporal-split).

P5.1 fixes this at the storage layer. The new `gateway::staging` module gives
every transient body a stable, session-partitioned home under:

```text
~/.claude/touring/staging/<session>/<file>
```

This is the foundation the **P5.2 staging registry** indexes so a staged path
resolves back to its origin and prior X2/X3 verdict.

## 3. VGP — genuine reuse of the planned symbols

The plan named `tee_dir` and `cleanup_tee` as reused symbols. Both were
verified in-repo (`sandbox_executor.rs:718` and `:765`) and are reused for
real, not merely mirrored:

- **`tee_dir`** — `staging_root()` derives the staging tree from
  `tee_dir().parent()`. The `HOME`-or-`/tmp` fallback resolution lives in
  exactly one place; the staging area is a sibling of the tee directory under
  the same `~/.claude/touring/` base.
- **`cleanup_tee`** — `gc_staging` calls it on the same retention window. The
  staging GC is the *unified* transient-area sweep: one call bounds both the
  staging tree and the tee logs. A failure reaching the tee tree never aborts
  the staging sweep (`tee_logs_removed` falls back to `0`).

`StagingArea`, `stage_path`, `gc_staging` confirmed new — `grep` returned no
prior definition.

## 4. Path-traversal safety

`sanitize_component` reduces any session id or file name to one safe path
component: every character outside `[A-Za-z0-9._-]` becomes `_` (so the result
can never carry a `/` or `\` separator), and a dots-only component (`.`, `..`)
is neutralised to `default`. A hostile id like `../../etc` cannot escape the
staging root — proven by `stage_path_sanitizes_traversal` (the resolved path
contains no `ParentDir` component) and `sanitize_component_neutralizes_dot_components`.

## 5. Staleness model

A session directory's *last activity* is the later of its own mtime and the
newest mtime among its direct children. Using the contained files catches
modifications that do not bump the parent dir mtime; using the dir's own mtime
as a floor keeps a freshly-created empty session alive through a long
retention window. A session is swept when last-activity is past the cutoff.

`gc_staging_resolves_env_root` exercises the `cleanup_tee` reuse
**non-destructively**: at `u64::MAX` retention `cleanup_tee` removes nothing
from the real tee tree, so the test never sets `TOURING_TEE_DIR` and cannot
race the `with_tee_dir` tests in `sandbox_executor`.
