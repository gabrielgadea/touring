## Executive Summary

Wave 12 fecha **dois loops órfãos** identificados pela skill Touring:

1. **B-301 RefactorRequired** estava emitindo, mas usava um proxy 1-dim (`avg_complexity`) em vez do `tdg.composite` (6-dim) já computado 100 linhas acima na mesma função. Wave 12 promove B-301 a usar a métrica completa (complexity + coverage + duplication + churn + entropy + antipatterns).

Ambos atendem **REGRA #0 (potencializar)** — zero código novo orphan, sinergia cross-subsystem documentada em `touring synergy`.

#### B.3 — Helper + counter (`touring-hooks`)

**Arquivo**: `crates/touring-hooks/src/pre_write.rs`

```rust
#[cfg(feature = "mpatch-fuzzy")]
pub fn emit_b302_if_low_confidence_expansion(
    file: &str,
    source: &str,
    preview: &PatchPreview,
) -> Option<PatchComplexityDelta> {
    const B302_CONFIDENCE_THRESHOLD: f32 = 0.7;
    let delta = PatchComplexityDelta::compute(source, &preview.preview, preview);
    if delta.is_expansion() && delta.confidence < B302_CONFIDENCE_THRESHOLD {
        // emit BlastWarning::PatchExpansion via tracing::warn! (RFC-100)
        // record gate_metrics counter
        record_diagnostic_b302_emitted();
        Some(delta)
    } else {
        None
    }
}
```

## Architecture Decisions

### A1 — Por que dissolver o bloco anônimo em vez de re-declarar `tdg` fora?
[confidence 0.95]

Bloco `{...}` linha 866-965 não tinha semântica (sem early return, sem retorno de valor, sem shadowing). Era apenas escopo de variáveis temporárias (`complexity_score`, `antipatterns_score`, `tdg`). Dissolvê-lo é zero-risk e preserva 100% da lógica.

Alternativas consideradas e rejeitadas:
- Salvar `tdg.composite` em variável pré-bloco — duplica esforço, perdia `grade_letter()`
- Mover B-301 para dentro do bloco — exigiria mover `metrics` reads também

### A2 — Por que B-302 é Severity::Warning, não Error?
[confidence 0.92]

B-301 (RefactorRequired) é Error porque o file precisa refactor ANTES do edit — não é seguro proceder. B-302 é diferente: o patch JÁ foi aplicado (dry-run) e funciona; apenas a **confidence** está baixa, sugerindo revisão manual. Bloquear seria conservador demais e quebraria o fluxo dos clientes.

### A3 — Por que wire em `cli_mpatch_preview` e não em `pre_write::run_returning`?
[confidence 0.90]

Three options trade-off:
- **A (chosen)**: `cli_mpatch_preview` — já chama `preview_patch`, source + preview em escopo, +1 campo opcional ao JSON. ~30 LOC.
- **B**: novo hook `pre-write-mpatch-preview` — exigiria entry no Hook Registry (174→175), dispatch_table, settings.json. ~120 LOC para mesmo benefício.
- **C**: `pre_write::run_returning` — pre_write nem sempre tem patch disponível; falsearia em writes sem mpatch.

### A4 — Por que `b302_diagnostic` é optional/null em vez de absent?
[confidence 0.88]

Backward compat: clientes legacy que ignoram o campo continuam funcionando. Mas o field SHAPE é estável (sempre presente, null ou objeto). Isso permite clients novos checarem `result["b302_diagnostic"].is_null()` em vez de `result.get("b302_diagnostic").is_some()` — semantica mais clara.
