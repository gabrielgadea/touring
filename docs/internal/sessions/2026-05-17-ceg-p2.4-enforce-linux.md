## 1. Offline dependency verification (the gate Gabriel mandated)

P2.4's plan symbols are "Reused: landlock crate; rustix". Both were verified
against the **offline** crate cache before any code was written:

| Dep | Cargo.lock | `~/.cargo/registry` cache | Verdict |
|-----|-----------|---------------------------|---------|
| `rustix` | ✅ 0.38.44 + **1.1.4** | ✅ `.crate` + extracted src | **available offline** |
| `landlock` | ❌ absent | ❌ no `.crate`, no src | **NOT available offline** |
| `libc` 0.2.183 | ✅ | — | only `SYS_landlock_*` syscall numbers — **no structs/consts** |

Kernel: **6.18.7** (landlock fully supported, ABI 6). `libc` 0.2.183 exposes
`SYS_landlock_create_ruleset/add_rule/restrict_self` but **not** the
`landlock_ruleset_attr` / `landlock_path_beneath_attr` structs nor the
`LANDLOCK_ACCESS_FS_*` constants.

## 2. Decision — split P2.4 by physical availability

**P2.4-A — rlimit — DELIVERED.** `rustix` is in the lockfile + cache, so
adding it as a direct dependency needs no network. Resource caps are safe,
testable, and complete.

**P2.4-B — landlock — DEFERRED (honest).** Implementing landlock now would
require hand-rolling the `#[repr(packed)]` `landlock_path_beneath_attr` struct
and raw `syscall()` calls for an **irreversible** security primitive
(`restrict_self` cannot be undone). A wrong struct field offset → the sandbox
**silently fails to protect** — worse than no sandbox. That is anti-elite.
landlock waits for an online sub-wave that adds the audited `landlock` crate
(v0.4.4). This is **not scope reduction**: the full enforcement architecture
+ the rlimit half + an explicit, observable degradation path all ship now.

## 3. What shipped — `crates/touring-hooks/src/capability/enforce_linux.rs`

| Symbol | Kind | Purpose |
|--------|------|---------|
| `apply_rlimit(&ResourceCaps) -> io::Result<usize>` | fn | `setrlimit` caps on the current process; **allocation-free** success path (fixed stack array + syscalls only) — async-signal-safe for `pre_exec` |
| `ResourceCaps` | struct | CPU / address-space / open-files / processes / file-size caps; `none()`, `sandboxed_defaults()`, `limits()`, `active_count()` |
| `CappedResource` | enum | Platform-independent resource class (rustix `Resource` mapping deferred to enforce time) |
| `EnforcementLevel` | enum | `KernelEnforced` / `ProcessIsolationOnly` / `Unsupported` — recorded by X9 LEARN |
| `EnforcementReport` | struct | `{ level, note }` — the landlock status report |
| `apply_landlock(&CapabilityProfile) -> EnforcementReport` | fn | **P2.4-B stub** — returns `ProcessIsolationOnly` (Linux) / `Unsupported` (other) **explicitly**, never a silent no-op |

`apply_rlimit` is allocation-free on purpose: it is built to run inside a
`Command::pre_exec` closure (post-fork, pre-exec), where only async-signal-safe
operations are valid. Each cap is set as both soft and hard limit so the child
cannot raise it. New dep: `rustix = { version = "1", features = ["process"] }`
(touring-hooks/Cargo.toml). Module registered + re-exported in
`capability/mod.rs`.

## 5. Deferred — P2.4-B landlock (online sub-wave)

When network is available: `cargo add landlock@0.4.4`, then `apply_landlock`
gains its real body — build a `Ruleset` from the profile's `FsRead`/`FsWrite`
allow-set under `CompatLevel::BestEffort`, map each `PathScope` to a
`PathBeneath` rule, `restrict_self()`, and upgrade the report to
`EnforcementLevel::KernelEnforced`. The dossier `docs/2026-05-17-ceg-best-practices.md`
("Linux landlock LSM") has the full API design. `EnforcementLevel::KernelEnforced`
is already defined — the deferred work fills in the path that produces it.

Optional later hardening: `apply_seccomp` behind a `ceg-seccomp` feature
(`seccompiler` crate) — defense-in-depth, not MVP-critical (best-practices §seccomp).
