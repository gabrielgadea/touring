## 1. What P3.3 adds

P3.2 captured and classified the call. P3.3 implements the two stages that
actually *judge* the code body without running it:

- **X2 STATIC** (`gateway/static_stage.rs`) — structural + per-language risk.
- **X3 VGP** (`gateway/vgp_stage.rs`) — symbol-reference verification.

`Verified` (X3's output state) is one of the two states the P3.1 typestate
proves structurally unskippable — code cannot reach a gate decision without
passing through it.

## 2. VGP — the three reused symbols

| Symbol | Location | Shape |
|--------|----------|-------|
| `validate_command` | `shared/bash_ast_validator.rs:144` | `fn(&str) -> Verdict` — structural destructive-command validator |
| `AstGrepRiskSignalLayer` engine | `shared/ast_grep_signal.rs` + `shared/risk_patterns.rs` | `scan_source_cached` + `pattern_set_for` + `format_matches` |
| `index find` | `cli_handlers_index.rs:114` (`cli_index_find`) | wired at P3.7 via a closure |

The risk layer's `enrich` is file-path-bound, but its **engine** is the
public, content-based `scan_source_cached(source, &PatternSet, budget)` —
exactly what an in-memory code body needs. `pattern_set_for(Lang)` returns a
set for the polyglot core five (Rust, Python, JS, TS, Go); P3.3 maps
`SandboxLanguage → Lang` for those five.

## 3. What shipped

### X2 — `gateway/static_stage.rs`

| Symbol | Purpose |
|--------|---------|
| `StaticSeverity` | `Clear < Warn < Block` — a derived total order |
| `StaticReport` | `severity` + `findings` + `risk_summary` |
| `StaticReport::analyze` | The X2 logic — structural check + risk scan, worst-severity-wins |
| `Execution::<Classified>::static_analyze` | The X0→…→X2 transition to `Analyzed` |

Two checks, worst severity wins:

1. **Structural** — `validate_command` flags the destructive-command catalogue
   (`rm -rf`, `find -delete`, `git push --force`, `git reset --hard`,
   `chmod -R 777`). It is structural: a destructive pattern inside a quoted
   string or comment does not fire — a P3.3 test asserts exactly that.
2. **Per-language risk** — for the polyglot core five the body is scanned with
   the `AstGrepRiskSignalLayer` engine; a Rust body with `.unwrap()` / `unsafe`
   / `panic!` yields a `risk_summary` and lifts severity to at least `Warn`.

`static_analyze` reads `raw().payload`, so it is sound even when an execution
reached `Classified` via bare `advance()` — a missing classification only
skips the language-aware scan.

### X3 — `gateway/vgp_stage.rs`

| Symbol | Purpose |
|--------|---------|
| `VgpReport` | `verified` + `unresolved` symbol lists; `all_resolved` / `checked` |
| `extract_symbols` | Lexical identifier extraction — `[A-Za-z_]\w*` runs ≥ 4, deduped, stop-listed |
| `Execution::<Analyzed>::vgp_verify` | The X2→X3 transition to `Verified` |

`vgp_verify<F: Fn(&str) -> bool>` is **closure-driven**: the index lookup is
injected, so the typestate transition stays pure and unit-testable. Production
wiring (P3.7) passes a closure backed by `touring index find`
(`cli_index_find`, verified to exist); a degraded caller with no index passes a
soft-pass closure; tests pass mocks. An unresolved reference is a yellow flag —
code about to run that names something the index does not know.

### Typestate extension — `gateway/typestate.rs`

The `Evidence` ledger gained `static_report` and `vgp_report`
(`Option<…>`). Each stage transition is the sole writer of its field; the
`..Evidence::default()` seed in `capture()` (added at P3.2) means no constructor
change was needed.
