## 1. The threat P1.6 closes

A script can be **written in one turn** and **executed in a later one**:

```text
turn N:    cat > /tmp/x.sh <<EOF ... EOF      # the gate sees a write
turn N+M:  bash /tmp/x.sh                     # the gate sees only "bash <path>"
```

At execution time `bash /tmp/x.sh` carries no code body — the CEG X2-X5
analysis would have nothing to inspect. P1.6 delivers the **`StagingRegistry`
stub** that makes the gate re-assert itself at execution time.

## 2. Plan correction (VGP — FIX-S4)

P1.6's plan lists "Reused symbols: `extract_file_context`". VGP verified
`extract_file_context` (`pre_bash.rs:276`) is a **generic first-path regex** —
it extracts *a* path but cannot distinguish a script *write* from a script
run. Using it for temporal-split detection would misclassify. P1.6 therefore
implements its own token-based extraction; `extract_file_context` stays in
place for its own use case (file-scoped failure context).

**Consequence:** P1.6 touches **zero existing code** — `sandbox_executor.rs`
(881 LOC, the file the plan named) is **not edited**. The only change to an
existing file is one `pub mod staging;` line in `lib.rs`. The deliverable is
100% greenfield — minimal blast radius, the elite-quality choice.

## 3. What shipped — `crates/touring-hooks/src/staging.rs`

| Symbol | Kind | Purpose |
|--------|------|---------|
| `classify_command` | fn | Stub-level token heuristic: `WritesScript` / `ExecutesScript` / `Neither` |
| `TemporalSplitSignal` | enum | The classification of a bash command |
| `StagedScript` | struct | A recorded staged script: `path`, `content_hash`, `origin`, `prior_verdict` |
| `StagingRegistry` | struct | In-memory `BTreeMap` of staged scripts — `register` / `lookup` / `gate_decision_for_exec` |
| `StagingGateDecision` | enum | `ReuseVerdict { verdict }` / `RequiresReanalysis { reason }` |
| `ReanalysisReason` | enum | `Unregistered` / `ContentChanged` / `NeverAnalysed` |

**The R9 guarantee.** The gate method `gate_decision_for_exec` — given a
`path` and the content hash observed now — yields: unregistered →
`RequiresReanalysis{Unregistered}`; hash differs from stage time →
`ContentChanged`; registered but never analysed → `NeverAnalysed`; known +
unchanged + analysed → `ReuseVerdict`. A staged-script run can therefore
**never** proceed on a stale or absent verdict — exactly risk R9's mitigation.

Detection is **stub-level** (whitespace tokenization); the full AST-based
classifier (quoting, pipelines, command substitution) is P5.2, which also
expands `StagingRegistry` into the indexed, cross-session `gateway/staging*.rs`.
