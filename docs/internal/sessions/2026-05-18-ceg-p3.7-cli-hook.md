## 1. What P3.7 adds

P3.7 is the **production wiring**: it turns the `X0..X7` typestate pipeline
(P3.1–P3.6) into something a CLI and a hook drive end to end. Three new files
across two crates:

- **`gateway/error.rs`** — `GatewayError`, the exhaustive error type.
- **`gateway/pre_exec.rs`** — `run_gateway` (the driver) + the pre-exec hook.
- **`cli/exec.rs`** (touring-server) — the `touring exec` CLI subcommand.

## 2. The X0..X9 mapping — and an honest boundary

`run_gateway` drives `X0..X7` (the typestate pipeline) with dependency-injected
closures, returning a `GatewayOutcome`.

- **X0..X7** — capture → classify → static → VGP → predict → sandbox →
  capability-gate → decision. Infallible once entered.
- **X8 EXECUTE** — the caller *honours* the verdict: `touring exec` reflects it
  in its exit code, the hook in its `HookResponse`. The *kernel-enforced
  supervised run* is CEG Pln2 **P4.2** (`run_supervised` + landlock).
- **X9 LEARN** — the `GatewayOutcome` (id + decision + full evidence ledger)
  *is* the structured learn-record; `touring exec -j` emits it verbatim.

### Critical safety finding — X5 is deferred by default

X5's value is *behavioural* — observe the code running. But the sandbox is not
yet filesystem-isolated (landlock is **P4.2**): a real dry-run of untrusted code
without isolation would *be* the harm the gateway exists to prevent. P3.7
resolves this honestly:

- **`deferred_dry_run`** — the default X5 runner. It does **not** execute; it
  returns a non-executing outcome marked `<X5-deferred:landlock-pending-P4.2>`.
  The gateway decides on the four *non-executing* analyses (X2 static, X3 VGP,
  X4 predict, X6 capability) — exactly what a gate should do before a safe room
  exists. The pre-exec hook and the default `touring exec` use this runner — it
  is safe for *any* input.
- **`guarded_dry_run`** — the opt-in real runner (`touring exec --sandbox`). It
  refuses the destructive-command catalogue (`rm -rf`, `git push --force`, …)
  via the structural validator **before any spawn**, and only ever runs what is
  cleared, in the rlimit + timeout sandbox.

This is the elite-and-honest call: a security gateway must never run untrusted
code without isolation. The real isolated dry-run goes live with P4.2.

## 3. What shipped

### `gateway/error.rs` — `GatewayError`

A **closed, exhaustive** error enum: `NotCodeBearing` / `EmptyPayload` /
`MissingCommand` / `MalformedHookInput`. No `Internal` catch-all — the `X0..X7`
pipeline cannot fail once entered (the typestate guarantees it), so the only
failure surface is the entry layer. `kind()` (stable label), `is_benign()`
(non-running / empty body → proceed, not a fault), `Display`, `Error`.

### `gateway/pre_exec.rs` — driver + hook

| Symbol | Purpose |
|--------|---------|
| `run_gateway` | The `X0..X7` driver — closure-injected, returns `GatewayOutcome` or `GatewayError` |
| `GatewayDeps` | The injected X3 / X4 / X5 / X6 dependencies |
| `GatewayOutcome` | id + `GateDecision` + `Evidence` — the X9 record (serialisable) |
| `soft_pass_symbol` / `neutral_outcome_history` | The graceful X3 / X4 production defaults |
| `deferred_dry_run` / `guarded_dry_run` | The safe-default and opt-in X5 runners |
| `run` / `run_returning` | The pre-exec hook handler (diverging / testable) |

The hook is **advisory by default**: `Allow` → silent, `Warn` / `Deny` →
injected context. A hard `HookResponse::Deny` (`permissionDecision: "deny"`)
fires only under `CEG_ENFORCE=1` — observe-before-enforce while the gateway is
still being hardened. It is **not** registered in `settings.json`: go-live is a
post-P4 step. The hook keeps the exit-0 invariant — `run()` always exits `0`
via `HookResponse::emit()`; the decision travels in the JSON payload. It is
fail-open at every step — malformed input or an internal hiccup → `Allow`.

### `cli/exec.rs` — `touring exec`

`touring exec '<command>'` drives a shell command through the gateway and
prints the verdict (human-readable, or JSON with `-j`). `--profile
sandboxed|readonly|trusted` (default `trusted`), `--sandbox` opts into the real
X5 runner, `--intent <text>`. Exit code follows the verdict — `Allow` / `Warn`
→ `0`, `Deny` → non-zero — so `touring exec 'cmd' && run-it` works.

## 4. VGP — plan symbols, reused symbols

The plan names new symbols `cli_exec` / `pre_exec`; the established codebase
conventions are `cli::exec::run` (every `cli/*.rs` exposes `run`) and
`gateway::pre_exec::run` / `run_returning` (every `pre_*` hook). Followed the
conventions — the plan names are logical, not literal. Reused, all verified by
direct source read: `HookResponse` (`hook_response.rs` — 6 variants, `emit()`
holds the exit-0 invariant), the `cli::common::command_table()` dispatch table,
the touring-hooks `main.rs` hook dispatch, `validate_command` (X2's structural
validator, reused by `guarded_dry_run`).
