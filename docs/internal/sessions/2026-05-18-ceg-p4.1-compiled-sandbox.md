## 1. What P4.1 fixes

The sandbox executor handled *interpreted* languages (Python, JS, Ruby, …) by
running `<runtime> -e/-c <source>`. **Go and Rust are compiled** — they have no
inline-source flag — and `resolve_language_args` admitted as much with two
broken placeholder arms:

```rust
SandboxLanguage::Go   => vec!["run".into(), "-".into()],  // requires stdin
SandboxLanguage::Rust => vec!["script".into()],           // requires cargo-script crate
```

`go run -` needs a source on stdin that the executor never pipes; `rust script`
assumes a third-party `cargo-script` tool. Neither ran. P4.1 implements the
real **tempfile + compile** path and resolves those comments — the acceptance
criterion.

## 2. What shipped — `sandbox_executor.rs`

| Symbol | Purpose |
|--------|---------|
| `spawn_and_capture` | The extracted shared core — spawn, read stdout under the timeout, await exit, blake3-hash + persist, tee a failure. `execute_in_sandbox` and both runners use it (was 60 inline lines — now DRY). |
| `apply_toolchain_env` | Credential whitelist **+ `PATH` + `HOME`** — a compiler toolchain cannot run without them. |
| `compile_and_run_go` | tempfile `main.go` + minimal `go.mod`, run via `go run .` |
| `compile_and_run_rust` | tempfile `main.rs`; `rustc` compile, then run the binary |

`execute_in_sandbox` now intercepts `SandboxGo` / `SandboxRust` at the top and
routes to the compiled-language runners before the interpreted-runtime path;
`resolve_language_args`'s Go/Rust arms became `Vec::new()` with a doc pointer.

### The env problem — `apply_toolchain_env`

`apply_credential_whitelist` does `env_clear()` then re-inherits **only**
credentials (`GH_TOKEN`, `AWS_*`, …) — no `PATH`, no `HOME`. That is right for
a self-contained interpreter, but it *starves a compiler*: `rustc` needs `PATH`
to find the linker, `go` needs `HOME` for its build cache. `apply_toolchain_env`
re-adds exactly `PATH` and `HOME` on top of the credential whitelist — the
minimum a toolchain cannot function without, nothing more.

### Compile failure is an outcome, not an error

`compile_and_run_rust` runs `rustc` first; a compile failure is returned as the
`SandboxResult` of that invocation (non-zero exit) and **the binary never
runs** — `rustc` processes source *text*, it does not execute the user's code.
`go run` fuses compile + run; a Go compile failure surfaces the same way.

### Isolation boundary — honest note

P4.1 makes the Go/Rust path *correct*; it inherits whatever isolation the
sandbox has — `rlimit` + wall-clock timeout today. Real **filesystem isolation
is P4.2** (landlock). The CEG gateway's X5 default runner remains
`deferred_dry_run` (P3.7) until P4.2 lands; `compile_and_run_*` is reached only
by the opt-in `guarded_dry_run` path and by direct `execute_in_sandbox` callers.
