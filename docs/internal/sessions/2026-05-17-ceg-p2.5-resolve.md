## 1. VGP — the plan's "reused: project_db"

P2.5's plan lists "Reused symbols: CapabilityProfile; project_db". Verified:
`project_db` is **not** a Rust API — `grep` across `touring-hooks/src` found it
only in a doc string and a test name. It denotes the daemon's per-project
SQLite DB (`<project>/.claude/touring/symbols.db`). **Wiring P2.5 to that DB
is a P3/P6 concern**, not P2.5's. P2.5 therefore delivers the *pure resolution
layer* plus a `serde`-serializable registry that the future persistence wave
will load/store. No I/O in P2.5 — resolution stays pure and testable.

## 2. What shipped — `crates/touring-hooks/src/capability/resolve.rs`

| Symbol | Kind | Purpose |
|--------|------|---------|
| `ProjectId` | struct | Canonical project identifier — trailing `/` trimmed, no symlink resolution (pure, per REGRA #17 determinism) |
| `ProjectProfileRegistry` | struct | `{ default_profile, overrides: BTreeMap<ProjectId, BuiltinProfile> }` — declare + resolve |
| `resolve_profile_for_project(&registry, &project)` | fn | The P2.5 entry point — deterministic `BuiltinProfile` resolution |
| `resolve_capability_profile(&registry, &project, ws, staging)` | fn | Convenience — resolves *and* builds the concrete `CapabilityProfile` |

**Determinism (the P2.5 acceptance criterion).** Resolution is a pure function
of `(registry, project)`. Overrides live in a `BTreeMap`, so the registry's
content, iteration, and serialization are independent of declaration order — a
test (`resolution_is_declaration_order_independent`) declares two projects in
both orders and asserts the registries are `==` and resolve identically.
`ProjectId` canonicalizes trailing separators so `/ws` and `/ws/` are one
project. Last-write-wins for a repeated declaration, documented.

**REGRA #0 — P2.5 wires P2.3's `BuiltinProfile`.** `BuiltinProfile` shipped
orphan in P2.3 (forward API). `resolve.rs` is its first real consumer:
`ProjectProfileRegistry` stores it and `resolve_capability_profile` calls
`BuiltinProfile::build`. The capability model is now internally connected.
