## 1. What P3.2 adds

P3.1 gave the gateway its typestate spine. P3.2 implements the first two
stages and makes them the first real *consumers* of that spine:

- **X0 CAPTURE** (`gateway/capture.rs`) — the gateway's admission filter.
- **X1 CLASSIFY** (`gateway/classify.rs`) — surface + language + code body
  extraction, attached to the typestate's `Evidence` ledger.

## 2. VGP — the two reused symbols

The plan lists "Reused (VGP): `command_shape`; `SandboxLanguage`". Both verified
against ground truth before use:

| Symbol | Location | Shape |
|--------|----------|-------|
| `SandboxLanguage` | `sandbox_executor.rs:99` | `enum`, 11 variants (JavaScript..Shell) |
| `command_shape` | `shared/bash_ast_validator.rs:294` | `fn(&str) -> Option<String>` — cluster-key normalizer |

`SandboxLanguage` derived only `Debug/Clone/Copy/PartialEq/Eq` — **no serde**.
The gateway records the classified language in its serde-persisted `Evidence`
ledger, so P3.2 adds `serde::Serialize`/`Deserialize` to it: a one-line,
purely-additive derive (REGRA #0 — the enum becomes serializable for every
caller, not just the CEG).

## 3. What shipped

### X0 — `gateway/capture.rs`

| Symbol | Purpose |
|--------|---------|
| `ExecSurface` | The surface taxonomy: `BashCommand` / `CtxExecute` / `Inferlet` / `NonExec` |
| `ExecSurface::detect` | Tool-name → surface (matches the trailing `__`-segment of MCP-namespaced names) |
| `ExecSurface::is_code_bearing` | `true` for every surface that runs code |
| `capture_tool_call` | The admission filter — builds an `Execution<Captured>`, or `None` for a `NonExec` call (a `Read`, a `Glob`) |

A non-running call is never admitted: the gateway only ever sees code.

### X1 — `gateway/classify.rs`

| Symbol | Purpose |
|--------|---------|
| `CodeBody` | The extracted body: `source` + `language` (`Option<SandboxLanguage>`) + `shape` |
| `Classification` | The X1 result: `surface` + `code_body` |
| `Classification::derive` | The extraction logic — surface, language, and (bash only) cluster shape |
| `sniff_language` | Best-effort language detection from a code body — shebang + a few syntactic markers; conservative (returns `None` rather than guess) |
| `Execution::<Captured>::classify` | The evidence-carrying X0→X1 transition |

A `Bash` command is unconditionally `SandboxLanguage::Shell` — definitional, not
a guess. Its cluster `shape` comes from the reused `command_shape`
(`"cargo test --release"` → `Some("cargo test")`). For other surfaces the
payload *is* the code, so the language is sniffed; a future refinement will
thread a caller-declared language through capture.

### Typestate extension — `gateway/typestate.rs`

The `Evidence` ledger gained one field — `classification: Option<Classification>`
— and `Execution` gained a crate-internal `evidence_mut()` so a stage transition
can attach its result. `Execution::capture` now seeds the ledger with
`..Evidence::default()`, so each future stage deliverable adds its field without
touching the constructor. `classify()` is the sole writer of `classification`,
so an `Execution<Classified>` always carries one at runtime.
