não deixar um `.git` aninhado na árvore do `touring`, exporte para fora primeiro:

```bash

cd /tmp/omarchy-skills-deck && git init -b main && git add . && git commit -m "…" && \
  gh repo create gabrielgadea/omarchy-skills-deck --public --source=. --push
```

## (B) Preservando a história do `touring` — só se você quiser

Exige commitar `client/omarchy/` antes (é o que falta para o `subtree` existir):


## Validador do plano — reinstalação pelo caminho oficial

```bash
omarchy plugin remove gabriel.skills-deck --yes
omarchy plugin add https://github.com/gabrielgadea/omarchy-skills-deck.git --enable --yes
omarchy plugin list | grep gabriel.skills-deck     # deve voltar 'enabled'
~/projects/touring/client/omarchy/bin/validate_p5.sh
```

`--yes` é **obrigatório** no `remove`: sem ele o script aborta com *"refusing to
continue without confirmation"* (`omarchy-plugin-remove:28`). O `remove` guarda se
o plugin estava habilitado antes de tirar (`was_enabled`), então o `--enable` do
`add` recoloca no mesmo lugar.
